# V8 ML TRAINING & FINE-TUNING PLAN

*Status: ACTIVE - Phase 1 (Audit)*

## 1. Core Principle: Honest Evaluation & Reproducibility
The V8 ML pipeline treats model training as a first-class engineering system physically separated from production runtime. We do not fake accuracy, hallucinate classes, or guess identities.

* **Rule:** New ML Class → Real Data Collection → Annotation → Training/Fine-tuning → Validation → Held-out Evaluation → Model Registry → Shadow Deployment → Approval → Production.

## 2. Dataset Governance
Every dataset used for fine-tuning the base YOLOX, Instance Segmentation, or Pose models must be versioned.

* **Dataset Register (`V8_DATASET_REGISTER.md`):** Must track Dataset ID, Version, Source Camera, Capture Date, Annotation Version, and Licensing.
* **Leakage Prevention:** Adjacent frames from the same video clip must *never* be split across Train and Validation/Test sets. Splits will be determined by time-boundary or camera-ID to enforce generalization.

## 3. Annotation & QA Pipeline
* **Tooling:** CVAT (or equivalent professional labeler).
* **QA Gates:** All annotations must pass automated scripts checking for:
  * Duplicate labels.
  * Impossible bounding boxes (out of bounds, 0x0 size).
  * Missing hard-negative labels.
  * Consistent class boundaries (e.g., distinguishing a 'box' from a 'pallet').

## 4. Hard-Negative Mining (Active Learning)
Low-confidence predictions and false positives generated by the V7 production models must be routed to a human-review queue.
* **Targets for Mining:** 
  * Wall photos, posters, and reflections triggering false 'Person' detections.
  * Shelves and shadows triggering false 'Product' or 'Case' detections.
  * Wrist-watches triggering false mobile phone detections.
* **Action:** Confirmed hard-negatives are annotated as background or explicitly labeled as their true class, added to Dataset `v_next`, and used for the next fine-tuning epoch.

## 5. Fine-Tuning Protocol
* **Base Models:** 
  * Object Detection: `yolox-x` (or `yolox-tiny` depending on node compute constraints).
  * Feature Extraction/Re-ID: `osnet_x1_0` or `arcface`.
* **Hyperparameter Tracking:** Every training run must log run ID, code version, dataset version, learning rate schedule, seed, and hardware profile.
* **In-Place Overwrites:** STRICTLY PROHIBITED. All new weights are versioned and stored alongside a cryptographic hash.

## 6. Evaluation & Promotion Gates
A model is only promoted when objective evidence proves superiority.

* **Evaluation Metrics Required:**
  * mAP (Mean Average Precision) across IoU thresholds 0.50:0.95.
  * Precision, Recall, and F1 Score (per-class).
  * False Positive Rate (especially on hard-negative test sets).
  * Inference Latency (p50, p95).
* **The Promotion Gate:**
  1. Achieves V7's 95% target baseline on real held-out data.
  2. Passes integration latency tests.
  3. Deploys silently as a "Shadow Model" alongside production to verify outputs without triggering physical alarms.
  4. Requires a human-approval database record to switch the active pointer.

## 7. Model Routing (Inference Scheduling)
To optimize compute, heavy specialist models are *only* invoked conditionally.
* **Pattern:** Fast YOLOX Tracker → Yields Bbox Crop → Routes to Specialist.
* Example: Person detected → Sent to Liveness/ArcFace.
* Example: Worker detected → Sent to Pose Estimator for OSHA ergonomics check.
* Example: Vehicle detected → Sent to ANPR pipeline.
